    glossAPI guide for LLMs (guide v1, CLI schema v1)¶

    glossAPI turns PDFs (local files or URLs you hand over) into clean text: it extracts the text layer, repairs fonts, cleans, routes bad pages to Greek OCR, splits sections, annotates them and exports. It is driven through a JSON CLI: every command prints one JSON envelope (schema v1).

    What glossAPI can do¶

    stage what it does devices packages
    download Fetch URL sources (HTTP; browser-assisted with the browser package). glossAPI does not search or scrape. cpu download
    extract Read the PDF text layer with PDFium and repair broken fonts (bundled Rust repair); Docling layout optional. cpu core
    clean Clean the extracted Markdown (Rust cleaner) and score its quality; route bad pages to OCR. cpu core
    ocr OCR the routed pages with the Greek OCR toolkit (the default plugin); output is text/Markdown. cpu, mps, cuda layout, ocr
    math Optional math/code enrichment with Docling (not executable by the streaming run yet). cpu layout
    sections Split documents into sections. cpu core
    annotate Classify sections with the packaged neutral classifier (product: annotated sections). cpu core
    export Write the document export (product: document export). cpu core

    Products (separate):

    • document_export (export stage): One record per document with its cleaned text and metadata (the export stage).
    • annotated_sections (annotate stage): Sections with their predicted types (the annotate stage). A separate product from the document export.

    The choices the user makes¶

    Files¶

    A versioned input manifest (manifest_version 1) of local paths or URLs with their original metadata; or --files PATH... for a quick plan.

    • Each entry names exactly one of: document_id, source_key, source_uri, path, url.
    • selection names the selection_ids to process; other entries are never opened, hashed or processed. An empty selection selects nothing (run refuses with empty_selection); omit it to process every entry.
    • Any metadata (and any other entry field) is carried verbatim to status --file and report.
    • glossAPI does not search or scrape. An LLM that found files elsewhere hands them over in a manifest.

    Devices¶

    • --device STAGE=cpu|mps|cuda:N (plan/run); only the stages listed with mps/cuda can use them.
    • install --device chooses the torch build for device-bound packages (cpu, cuda126, cuda132, mps); one device profile per environment.
    install device profile platforms (torch index)
    cpu linux-x86_64 (https://download.pytorch.org/whl/cpu); macos-arm64 (https://pypi.org/simple)
    cuda126 linux-x86_64 (https://download.pytorch.org/whl/cu126)
    cuda132 linux-x86_64 (https://download.pytorch.org/whl/cu132)
    mps macos-arm64 (https://pypi.org/simple)

    Purposes:

    • core: The base install: text-layer extraction (PDFium with the bundled Rust font repair), cleaning, sections, annotation with the packaged neutral classifier, and export. Always installed with glossapi.
    • download: HTTP downloads of URL sources (aiohttp, YAML policies).
    • browser: Browser-assisted downloads (Playwright, Pillow); includes download. Browser engines are a separate explicit python -m playwright install chromium step that glossapi never runs.
    • layout: Docling 2.81 layout extraction and math/code enrichment; needs a device-specific torch build.
    • docling: Alias of layout (kept so existing glossapi[docling] installs resolve).
    • annotate: No extra packages: the packaged neutral section classifier runs on core numpy. Kept so existing glossapi[annotate] installs resolve.
    • annotate-legacy: scikit-learn 1.6.1 and joblib, only to load an explicitly supplied *.joblib classifier or to train one.
    • font-repair: The Python reference font repair (pypdf, fontTools); used only when the Rust repair is missing or requested explicitly.
    • docs: Documentation tooling (mkdocs); no pipeline capability.
    • ocr: The Greek OCR toolkit (the default OCR plugin, pinned to one commit) with its Docling, torch and ONNX pins.

    Settings¶

    • debug=off (default): An intermediate is released only after every planned reader has succeeded on its exact hash. Supplied files, selected final products, evidence and the ledger are kept.
    • debug=on: Keep every stage's intermediates and attempts, including bounded inner HTTP request bodies.
    • memory_saving=normal (default): Never delete a supplied original or a downloaded file.
    • memory_saving=extreme: Delete only downloads this run owns, after the last planned reader succeeds and outputs are durable. Never a supplied original, another run's file, or a path reached through a link. Requires a disk budget.

    Stages are fixed at the start of a run, and evaluation adds no readers. A plan amendment that adds a reader is a new plan; it cannot justify a past deletion.

    Workflow¶

    1. capabilities: glossapi capabilities --json. What is installed and runnable now: every stage, its packages, the visible devices. Read-only.
    2. catalog: glossapi capabilities --catalog --json. Every optional package with what it adds, devices, measured install size, licences and install state.
    3. install (preview): glossapi install --device cpu --package download --json. Dry run: the exact commands and what they would change. Nothing runs. Show it to the user.
    4. install (after the user agrees): glossapi install --device cpu --package download --yes --json. Runs exactly the previewed commands, then re-checks capabilities and reports what changed.
    5. plan (preview): glossapi plan --corpus CORPUS --manifest MANIFEST.json --json. The exact targets, exclusions, required capabilities, device allocation and deletion policy. Writes nothing.
    6. run: glossapi run --corpus CORPUS --plan PLAN.json --json. Runs the saved plan; refuses if any input byte, setting or installed capability changed since the preview.
    7. retry failed tasks (after the user agrees): glossapi run --corpus CORPUS --resume RUN_ID --retry-failed --json. An interrupted or lost attempt (killed worker, timeout) is retried automatically, at most 3 attempts per task, and every interrupted attempt counts. Past that budget the task stays failed; --retry-failed is an explicit, operator-authorised retry of the failed tasks of that run.
    8. status: glossapi status --corpus CORPUS --json. Progress and per-stage counts of the latest run.
    9. report: glossapi report --corpus CORPUS --json. The final census: every requested source exactly once.
    10. report --why: glossapi report --corpus CORPUS --why DOCUMENT --json. Why a document ended as it did, from the ledger alone (also after intermediates are released).

    {
  "manifest_version": 1,
  "documents": [
    {
      "url": "https://example.org/a.pdf",
      "selection_id": "a",
      "metadata": {
        "title": "Found by the LLM"
      }
    },
    {
      "path": "/absolute/path/b.pdf",
      "selection_id": "b"
    }
  ],
  "selection": [
    "a",
    "b"
  ],
  "products": [
    "document_export"
  ],
  "settings": {
    "debug": "off",
    "memory_saving": "normal"
  }
}
    • Paths are absolute; URLs are fetched by the download stage only when it is planned.
    • Show the user plan --json before run; run the saved plan with run --plan.
    • Downloads are public targets only: a URL with userinfo or a credential query field is refused (credentials_unsupported).

    Typed errors on the decision path¶

    code command exit meaning
    device_required install 2 No --device was given; choose one device profile: cpu, cuda126, cuda132, mps.
    conflicting_device_profiles install 2 More than one device profile was requested; an environment holds one torch build.
    unknown_device install 2 The device profile is not one of cpu, cuda126, cuda132, mps.
    device_unsupported_on_platform install 2 This platform has no such device profile (mps needs Apple Silicon macOS; cuda126/cuda132 need Linux).
    unknown_package install 2 A requested package is not in the catalog (glossapi capabilities --catalog).
    package_device_unsupported install 2 A requested package does not support the device profile (its lock did not resolve or no measured platform has it).
    installed_device_profile_conflict install 2 The environment already holds a torch build of another device profile; use a separate environment for this device.
    requirements_unavailable install 2 glossapi is neither a source checkout nor an installed distribution, so its profiles cannot be read.
    installer_unavailable install 2 Neither pip (in this interpreter) nor uv (on PATH) is available to run --yes.
    install_command_failed install 2 An install command exited non-zero; later commands did not run. data.executed has the output tail and data.changes what changed before the failure.
    device_unsupported_for_stage plan, run 2 A device choice the stage or machine cannot honour; plan keeps its preview in data.
    device_option_conflict plan, run 2 A device choice the stage or machine cannot honour; plan keeps its preview in data.
    device_unavailable plan, run 2 A device choice the stage or machine cannot honour; plan keeps its preview in data.
    missing_capability run 2 plan exits 0 with execution.ready false and the install commands; run refuses before writing.
    empty_selection run 2 The manifest selects no entry (selection: [] or an empty document list): plan exits 0 with zero targets, every entry in exclusions and execution.ready false; run refuses before writing. Omit selection to process every entry.
    invalid_plan run --plan 2 The file is not plan --json output (or its data object).
    plan_hash_mismatch run --plan 2 The saved plan no longer matches: re-run plan and show the new preview.
    plan_source_changed run --plan 2 The saved plan no longer matches: re-run plan and show the new preview.
    plan_capability_changed run --plan 2 The saved plan no longer matches: re-run plan and show the new preview.
    disk_budget_required plan, run 3 memory_saving=extreme needs positive disk_budget_bytes, max_source_bytes and max_attempt_bytes.
    disk_guard_unavailable plan, run 3 memory_saving=extreme needs dedicated size-limited corpus and staging filesystems whose capacities fit the budget; an ordinary shared volume is refused.
    post_close_edit run 3 A corpus copy the last run left unflushed (export.jsonl, a metadata parquet) was changed after that run closed; it is kept. Move or delete it (it is republished from the managed source) or use another corpus.
    unresolved_recovery run 3 A corpus product is not in the state the ledger expects and could not be made so safely. At a run start or a repeated publication: recovery found a file it must repair (a copy the last run left unflushed, or bytes a failed attempt put in place) but could not (hard-linked, contradictory lock records, path replaced, managed source changed or missing); the file is kept and the run stops there. At the completion gate: the run's work was done, but a product differs from its expected state; the run is not completed. Remove the cause (e.g. the extra hard link) and resume.
    credentials_unsupported plan, run 2 A source URL carries userinfo (user:pass@) or a credential query/fragment field (token, key, signature, ...), or a download setting would send credentials (domain_cookies, credentials): glossAPI downloads public targets only. Refused before anything is planned, recorded or fetched; supply the public URL.
    invalid_manifest plan, run 2 A malformed manifest entry; details.field and details.index say where.
    unsupported_manifest_version plan, run 2 This glossAPI reads manifest_version 1 only.

    Exit codes: 0 success; 1 ran and found failures (status/run with failed documents; doctor with an error check); run lists each failed task and unavailable source in errors (code = the ledger reason code); 2 a typed error (errors[0].code); 3 a policy or disk conflict, or a run waiting for disk.
